# 우리기획 서비스 이관 CSV 필드 명세

> **목적**: 서비스 메인 통합본에서 정리한 데이터를 우리기획 DB의 `wr_company_t`와 세 종류의 `wr_content_t` 콘텐츠로 안전하게 적재한다.
>
> **범위**: 이 문서는 현재 확정된 *CSV 입력 규칙*이다. 실제 DB DDL의 `VARCHAR` 길이, SQL `NOT NULL`, 물리 FK 정의는 제공되지 않았으므로 확인되지 않은 DB 제약을 추정하지 않는다.

---

## 1. 먼저 이해할 구조

```text
[업체] wr_company_t
   ├── [담당자] wr_content_t / 담당자 모듈
   ├── [프로젝트] wr_content_t / 프로젝트 모듈
   └── [서비스] wr_content_t / 서비스 모듈
                         └── parent_idx → 프로젝트 콘텐츠
```

### 이관 CSV 네 개

| 파일 | 적재 대상 | 한 줄 설명 |
|---|---|---|
| `company.csv` | `wr_company_t` | 업체를 먼저 만든다. 모든 콘텐츠의 `company_idx` 기준이다. |
| `contact_module.csv` | `wr_content_t` 담당자 모듈 | 업체에 속한 고객/서브 담당자 연락처다. |
| `project_module.csv` | `wr_content_t` 프로젝트 모듈 | 업체에 속한 프로젝트다. 서비스의 상위 항목이다. |
| `service_module.csv` | `wr_content_t` 서비스 모듈 | 실제 운영·테스트 서비스다. URL 및 민감 계정 정보를 가진다. |

### 이관 대상 선택 규칙

정제 인계본에서 이미 검토된 다음 항목만 CSV에 포함한다.

```text
migrate = 1
AND company.merged_into 가 비어 있음
AND 해당 업체에 연결된 사이트·서비스·프로젝트
```

`migrate=0` 또는 병합 대상 업체는 자동 적재하지 않는다.

## 2. 모든 파일의 공통 규칙

| 항목 | 규칙 | 설명 |
|---|---|---|
| 파일 인코딩 | UTF-8 with BOM (`utf-8-sig`) | Excel에서 한글이 깨지지 않도록 BOM을 포함한다. |
| CSV 구분 | 쉼표(`,`) | 쉼표·줄바꿈·큰따옴표가 값에 있으면 RFC 4180 방식으로 큰따옴표로 감싼다. |
| 신규 `idx` | UUID v7 | `xxxxxxxx-xxxx-7xxx-[89ab]xxx-xxxxxxxxxxxx` 형식의 소문자 36자 ID다. |
| 원본 `idx` | 기존 UUID v7 유지 | 정제 인계본에서 이미 생성·연결 검증한 ID는 새로 만들지 않는다. |
| 날짜 | `YYYY-MM-DD` 또는 빈 값 | 실제 시작/종료일이 없으면 빈 값이다. `2999-12-31` 같은 임의 날짜는 넣지 않는다. |
| 미확인 코드 | `0` | `status`, `type`이 빈 값 또는 `unknown`일 때만 `0`을 쓴다. |
| 일반 미확인값 | 빈 값 | 이름·URL·연락처·메모 등은 추정하거나 채우지 않는다. |
| 민감정보 | 서비스 `content_raw.accounts`만 | 계정 ID·비밀번호·DB 관리 URL은 서비스 행에만 둔다. |

## 3. 관계 키와 고정 모듈 ID

| 콘텐츠 | `module_idx` | 연결 규칙 | 설명 |
|---|---|---|---|
| 담당자 | `01a05700-8c1d-7cd4-8b2d-fac77f865a9f` | `company_idx` 필수 | 담당자는 외부 고객/서브 담당자다. |
| 프로젝트 | `01a05701-ed99-7cfa-841e-ec6f6c9922a0` | `company_idx` 필수 | 업체의 프로젝트 콘텐츠다. |
| 서비스 | `01a05702-067e-729b-85ab-deb5b0836082` | `company_idx`, `parent_idx` 필수 | 서비스는 업체와 프로젝트 양쪽에 연결된다. |

### 참조 제약

| 필드 | 참조 대상 | 제한 | 설명 |
|---|---|---|---|
| 모든 콘텐츠의 `company_idx` | `company.csv.idx` | 반드시 존재 | 콘텐츠가 어느 업체에 속하는지 나타낸다. |
| 서비스 `parent_idx` | `project_module.csv.idx` | 반드시 존재 | 서비스의 상위 프로젝트를 나타낸다. |
| 프로젝트 `ref_idx` | 없음 | 현재는 빈 값 | 업체·고객 연결용이 아니다. 현재 원본에서 사용 근거가 없다. |
| 모든 콘텐츠의 `receiver_idx` | 내부 member ID | 현재는 빈 값 | 외부 고객 담당자는 이 값이 아니라 담당자 모듈로 관리한다. |

# 4. `company.csv` — 업체 (`wr_company_t`)

**역할**: 회사의 기준 레코드다. 담당자·프로젝트·서비스의 `company_idx`는 이 파일의 `idx`를 참조한다.

현재 최소 이관에서는 **검증된 업체 ID와 업체명만** 입력한다. 주소·사업자번호·대표 연락처처럼 원본에 구조화되어 있지 않은 값은 빈 값으로 둔다.

| 필드 | 형식 | 필수 | 값/제한 | 설명 | 현재 이관 |
|---|---|:---:|---|---|---|
| `idx` | UUID v7 | 예 | 중복 불가 | 업체의 고유 식별자이자 모든 하위 콘텐츠의 참조 기준이다. | 입력 |
| `company_name` | UTF-8 텍스트 | 예 | 공백만 불가 | 화면·검색에 표시할 업체명이다. 정제 인계본의 대표 업체명을 유지한다. | 입력 |
| `company_number` | 텍스트 | 아니오 | 원본에 있을 때만 | 사업자등록번호 등 업체 등록번호다. | 빈 값 |
| `company_phone` | 텍스트 | 아니오 | 원본에 있을 때만 | 대표 전화번호다. 담당자 개인 번호를 넣지 않는다. | 빈 값 |
| `company_email` | 이메일 텍스트 | 아니오 | 원본에 있을 때만 | 대표 이메일이다. 담당자 개인/부서 이메일을 넣지 않는다. | 빈 값 |
| `company_manager_name` | UTF-8 텍스트 | 아니오 | 원본에 있을 때만 | 업체 대표 담당자명이다. | 빈 값 |
| `company_manager_phone` | 텍스트 | 아니오 | 원본에 있을 때만 | 업체 대표 담당자 연락처다. | 빈 값 |
| `company_manager_email` | 이메일 텍스트 | 아니오 | 원본에 있을 때만 | 업체 대표 담당자 이메일이다. | 빈 값 |
| `company_address` | UTF-8 텍스트 | 아니오 | 원본에 있을 때만 | 기본 주소다. | 빈 값 |
| `company_address_2` | UTF-8 텍스트 | 아니오 | 원본에 있을 때만 | 상세 주소다. | 빈 값 |
| `company_extras` | JSON/텍스트 | 아니오 | 임의 JSON 금지 | 별도 구조가 확정된 부가 업체 정보용이다. | 빈 값 |
| `tags` | 공백 구분 텍스트 | 아니오 | 임의 태그 생성 금지 | 업체 검색 태그다. | 빈 값 |
| `admin_idx` | 내부 member ID | 아니오 | 실제 member ID만 | 우리기획 내부 담당 관리자 연결값이다. | 빈 값 |

# 5. `contact_module.csv` — 담당자 콘텐츠

**역할**: 고객사 외부 담당자와 서브 담당자의 연락처를 저장한다. 내부 작업자·회원 ID를 저장하는 곳이 아니다.

| 필드 | 형식 | 필수 | 값/제한 | 설명 | 현재 이관 |
|---|---|:---:|---|---|---|
| `idx` | UUID v7 | 예 | 중복 불가 | 담당자 콘텐츠의 고유 ID다. | 입력 |
| `module_idx` | UUID | 예 | 담당자 모듈 ID 고정 | 이 행이 담당자 콘텐츠임을 판별한다. | 입력 |
| `company_idx` | UUID v7 | 예 | `company.csv.idx` 참조 | 담당자가 속한 업체다. | 입력 |
| `name` | UTF-8 텍스트 | 예 | 공백만 불가 | 원본에서 확인된 담당자명이다. | 입력 |
| `content` | UTF-8 텍스트 | 아니오 | 임의 메모 금지 | 추가 설명/메모 필드다. | 빈 값 |
| `contact` | 전화번호 텍스트 | 아니오 | 원본 표기 보존 | 휴대전화·일반전화 등 원본 연락처다. 형식을 강제 변환하지 않는다. | 입력 가능 |
| `email` | 이메일 텍스트 | 아니오 | 원본 표기 보존 | 원본 이메일 주소다. | 입력 가능 |

# 6. `project_module.csv` — 프로젝트 콘텐츠

**역할**: 서비스의 상위 프로젝트를 저장한다. 한 서비스는 반드시 하나의 프로젝트 `idx`를 `parent_idx`로 참조한다.

| 필드 | 형식 | 필수 | 값/제한 | 설명 | 현재 이관 |
|---|---|:---:|---|---|---|
| `idx` | UUID v7 | 예 | 중복 불가 | 프로젝트 콘텐츠의 고유 ID다. | 입력 |
| `module_idx` | UUID | 예 | 프로젝트 모듈 ID 고정 | 이 행이 프로젝트 콘텐츠임을 판별한다. | 입력 |
| `ref_idx` | UUID/빈 값 | 아니오 | 현재 빈 값만 | 보조 참조 필드다. 고객·업체 관계에 사용하지 않는다. | 빈 값 |
| `company_idx` | UUID v7 | 예 | `company.csv.idx` 참조 | 프로젝트 소속 업체다. | 입력 |
| `title` | UTF-8 텍스트 | 예 | 공백만 불가 | 원본 프로젝트명이다. | 입력 |
| `status` | 정수 코드 | 예 | `1`, `-1`, `0` | `1=운영`, `-1=비운영/종료`, `0=원본 값 없음/unknown`이다. | 입력 |
| `date_start` | 날짜/빈 값 | 아니오 | `YYYY-MM-DD` | 원본 시작일이다. | 입력 가능 |
| `date_end` | 날짜/빈 값 | 아니오 | `YYYY-MM-DD` | 원본 종료일이다. 없는 경우 비워 둔다. | 입력 가능 |
| `type` | 정수 코드 | 예 | 현재 `0` | 프로젝트 유형 값이 원본에 없으므로 `0`이다. | `0` |
| `url` | URL/호스트 텍스트 | 아니오 | 원본값만 | 프로젝트 단위 URL 필드다. | 빈 값 |
| `tags` | 공백 구분 텍스트 | 아니오 | 임의 태그 생성 금지 | 프로젝트 검색 태그다. | 빈 값 |
| `receiver_idx` | 내부 member ID/빈 값 | 아니오 | 외부 담당자 ID 금지 | 내부 담당자 연결 필드다. | 빈 값 |
| `is_hidden` | `0`/`1`/빈 값 | 아니오 | 현재 미사용 | 프로젝트 공개 제어 필드다. | 빈 값 |
| `content_raw` | JSON/빈 값 | 아니오 | 현재 미사용 | 프로젝트의 비검색 원본 데이터 필드다. | 빈 값 |
| `content` | UTF-8 텍스트 | 아니오 | 임의 메모 금지 | 사람이 읽는 프로젝트 메모다. | 빈 값 |

# 7. `service_module.csv` — 서비스 콘텐츠

**역할**: 실제 운영·테스트 서비스다. 실제 서비스 도메인은 일반 `url` 열에 넣고, 계정 정보는 `content_raw.accounts`에 넣는다. 호스팅 주소는 FTP 계정의 `host`에 둔다.

| 필드 | 형식 | 필수 | 값/제한 | 설명 | 현재 이관 |
|---|---|:---:|---|---|---|
| `idx` | UUID v7 | 예 | 중복 불가 | 서비스 콘텐츠의 고유 ID다. | 입력 |
| `module_idx` | UUID | 예 | 서비스 모듈 ID 고정 | 이 행이 서비스 콘텐츠임을 판별한다. | 입력 |
| `parent_idx` | UUID v7 | 예 | `project_module.csv.idx` 참조 | 서비스를 상위 프로젝트에 연결한다. | 입력 |
| `company_idx` | UUID v7 | 예 | `company.csv.idx` 참조 | 서비스 소속 업체다. | 입력 |
| `title` | UTF-8 텍스트 | 예 | 공백만 불가 | 원본 서비스명이다. | 입력 |
| `status` | 정수 코드 | 예 | `1`, `-1`, `0` | `1=운영`, `-1=비운영/종료`, `0=원본 값 없음/unknown`이다. | 입력 |
| `date_start` | 날짜/빈 값 | 아니오 | `YYYY-MM-DD` | 원본 서비스 시작일이다. | 입력 가능 |
| `date_end` | 날짜/빈 값 | 아니오 | `YYYY-MM-DD` | 원본 서비스 종료일이다. 없는 경우 비워 둔다. | 입력 가능 |
| `type` | 정수 코드 | 예 | `1`, `2`, `3`, `0` | `1=실제 운영`, `2=테스트/개발`, `3=샘플`, `0=원본 값 없음/unknown`이다. | 입력 |
| `url` | 쉼표 구분 도메인 | 아니오 | 원본 서비스 도메인만 | 실제 서비스 도메인이다. 도메인이 여러 개면 대표 도메인을 먼저 두고 쉼표로 연결한다. 호스팅 주소는 넣지 않고 FTP 계정의 `host`에 둔다. 주소를 새로 만들거나 추정하지 않는다. | 입력 가능 |
| `tags` | 공백 구분 텍스트 | 아니오 | 임의 태그 생성 금지 | 서비스 검색 태그다. | 빈 값 |
| `receiver_idx` | 내부 member ID/빈 값 | 아니오 | 외부 담당자 ID 금지 | 내부 담당자 연결 필드다. | 빈 값 |
| `is_hidden` | `1` | 예 | 모든 이관 서비스 `1` | 계정 원문을 보호하기 위해 서비스 자체를 숨김 처리한다. | `1` |
| `content_raw` | JSON/빈 값 | 계정 있을 때 예 | 아래 `accounts` 명세만 허용 | FTP·DB·관리자 계정이다. | 입력 가능 |
| `content` | UTF-8 텍스트 | 아니오 | 임의 메모 금지 | 사람이 읽는 서비스 메모다. | 빈 값 |

# 8. `content_raw.accounts` JSON 명세

`content_raw`는 **계정 정보 전용**이다.

- 최상위 키: `accounts` **하나만** 허용
- 계정이 없으면 `content_raw`는 빈 CSV 값
- `{}`는 사용하지 않음
- `urls`, `access_check`, `status`, `type`, `risk_flags`, 사이트·프로젝트 메모는 넣지 않음

## 허용 JSON 예시

```json
{
  "accounts": [
    {
      "type": "FTP",
      "host": "<원본_호스팅주소>",
      "id": "<원본_접속아이디>",
      "pw": "<원본_접속비밀번호>"
    },
    {
      "type": "DB_iwinv",
      "url": "<원본_phpMyAdmin_URL>",
      "id": "<원본_DB_아이디>",
      "pw": "<원본_DB_비밀번호>"
    },
    {
      "type": "admin",
      "id": "<원본_관리자아이디>",
      "pw": "<원본_관리자비밀번호>"
    }
  ]
}
```

## `accounts[]` 필드 상세

| JSON 경로 | 형식 | 필수 | 허용값/제한 | 설명 |
|---|---|:---:|---|---|
| `accounts` | JSON 배열 | 예 | 계정 객체 1개 이상 | 계정 목록이다. 계정이 없으면 배열 자체를 만들지 않고 `content_raw`를 비운다. |
| `accounts[].type` | 문자열 | 예 | `FTP`, `DB_iwinv`, `DB`, `admin` | 계정 종류다. `DB_iwinv`는 iwinv DB 계정, `DB`는 iwinv 외 DB 계정이다. |
| `accounts[].host` | 호스트 문자열 | 아니오 | 원본 호스팅 주소만 | 서비스의 호스팅 주소다(호스팅사 서버 주소, 없으면 서버 IP). **`type=FTP` 계정에만** 넣고 DB·admin 계정에는 넣지 않는다. 원본에 없으면 키 자체를 생략한다. |
| `accounts[].id` | 문자열 | 아니오 | 원본 계정 ID만 | 접속/DB/관리자 ID다. 원본에 없으면 키 자체를 생략한다. |
| `accounts[].pw` | 문자열 | 아니오 | 원본 비밀번호만 | 비밀번호다. 원본에 없으면 키 자체를 생략한다. |
| `accounts[].url` | URL 문자열 | 아니오 | 원본 DB 관리 URL만 | phpMyAdmin 등 DB 관리도구 주소다. 원본에 없으면 키 자체를 생략한다. |

계정 객체에는 `type`, `host`, `id`, `pw`, `url` 외 키를 넣지 않는다.

> **보안**: `service_module.csv`는 실제 자격증명을 포함한다. 공개 Git 저장소, 일반 문서, 공개 채널에는 올리지 않는다.

# 9. 적재 전 검증 체크리스트

1. CSV가 정확히 4개인지 확인한다.
2. 각 파일의 헤더 순서가 이 명세와 같은지 확인한다.
3. 모든 `idx`가 UUID v7인지 확인한다.
4. 모든 `company_idx`가 `company.csv.idx`에 존재하는지 확인한다.
5. 모든 서비스 `parent_idx`가 `project_module.csv.idx`에 존재하는지 확인한다.
6. 프로젝트·서비스의 `status`, `type`에 빈 값 또는 `unknown`이 없는지 확인한다.
7. `service_module.csv.is_hidden`이 모두 `1`인지 확인한다.
8. `content_raw`가 유효 JSON인지 확인한다.
9. `content_raw`의 최상위 키가 `accounts`뿐인지 확인한다.
10. 모든 계정 객체의 키가 `type`, `host`, `id`, `pw`, `url`만으로 구성됐는지 확인한다.
11. `host`가 FTP 계정에만 있고, 한 서비스의 FTP `host`가 모두 같으며, 그 값이 서비스 `url`에 들어 있지 않은지 확인한다.
